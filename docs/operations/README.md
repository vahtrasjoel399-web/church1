# Эксплуатация и восстановление

## Конфигурация

Локальные ключи и модели задаются в `.env`; сервер читает `.dev.vars`, созданный `npm run configure`. Затем перезапустите `npm run dev`. В облаке секреты задаются через Wrangler; изменение локального файла не меняет облачный секрет. Команды публикации находятся в корневом README.

`OPENAI_API_KEY` используется для распознавания. Ключ перевода определяется `TRANSLATION_PROVIDER`: `GEMINI_API_KEY`, `OPENAI_API_KEY`, `DEEPSEEK_API_KEY` или `ANTHROPIC_API_KEY` (провайдер `anthropic`). Для Claude модель и effort хранятся в настройках комнаты и выбираются на пульте; по умолчанию `claude-haiku-4-5`. Effort ограничен уровнями low–high: на фразу даётся 12 секунд. Для моделей кроме Haiku включён серверный резерв при отказе (`fallbacks: "default"`), чтобы одна отклонённая фраза не останавливала сеанс. SDK Anthropic вызывается без повторов, чтобы не платить дважды за одну фразу. `TRANSLATION_MODEL` должен соответствовать провайдеру. Поле `ready` пульта означает наличие ключей, а не успешную проверку доступа.

## Разбор сбоев

| Симптом | Значение и действие |
| --- | --- |
| Распознавание 401 / `invalid_api_key` | Провайдер отверг ключ. Обновить ключ в нужной среде, применить настройки и перезапустить локальный сервер |
| Перевод 400, приложение 502 | Провайдер отверг запрос. Проверить модель и поддерживаемые параметры; записать провайдера, модель и машинный код ошибки |
| 401/403 перевода | Проверить ключ и доступ к выбранной модели |
| 429 AI | Проверить лимиты провайдера и подождать перед новым сеансом |
| Таймаут перевода | Лимит fetch — 12 секунд. Проверить связь; повтор может быть платным |
| Ошибка соединения перевода | Проверить сеть сервера, DNS и доступ к провайдеру |
| `Realtime hangup failed after session termination` | Сессия приложения уже остановлена; внешний hangup не подтверждён. Его таймаут 1,5 секунды не объясняет предшествующий отказ перевода |
| Отставание очереди / распознавания | Проверить аудиовход, сеть и задержки; начать новый сеанс после устранения причины |
| Экран пуст | Проверить активность сеанса, скрытие, срок подписи и актуальность ссылки зрителя |

При ошибке закрытия проверьте состояние/расходы у провайдера. Не считайте сообщение об остановке приложения доказательством успешного внешнего hangup. Проверка старого `call_id` при старте не гарантирует повторное закрытие: текущий `terminate` очищает этот идентификатор и после ошибки.

## Проверка перед служением

Выберите аудиовход, убедитесь в движении уровня, проверьте короткий русский фрагмент и появление английского текста на целевом экране. Проверьте остановку микрофона и очистку подписи. После изменения модели сверяйте тарифы или задавайте переопределения цен; ориентир бюджета не является точным счётом провайдера.

Для диагностики сохраняйте время, действие, HTTP-статус, провайдера/модель и машинный код ошибки. Не публикуйте ключи, аудио и полные тексты проповеди в логах. Метрики без текста доступны в пульте.
